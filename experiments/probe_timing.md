## 冻结口径在探针中的落实（结构性修正）

1. **弃光只能来自光伏**：内核用 `pv_used ≤ pv_available` 表达，`pv_curtail = pv_available − pv_used` 由恒等式推导；T3/T4 锁死"弃光吞购电"漏洞。
2. **Q1 购电语义**：`grid_contract = grid_delivered`，`grid_unused = 0`，`grid_emergency = 0`；目标只算 `Σ price·grid_contract`。Q2 的紧急购电/未使用合同电规则未混入。
3. **计划版本结构**（`src/core/executor.py`）：`PlanRecord` 不可变追加（target_slot/issue_time/plan_version/previous_version/quantity/increase/decrease），当前只实现单版本；Q3 多次结算公式未冻结。
4. **防泄漏接口**（`src/core/data_io.py`）：所有读取函数要求 `as_of`，附件读取断言发布时间 ≤ as_of；为 walk-forward 预留 `decision_time` 截断。
5. **模板按槽位对列**：`template_io.py` 写读回读按 slot_id 逐列验证区间标签逐字符一致，禁止字符串模糊匹配。

## 待人类确认（不阻塞 Q1，阻塞 Q2/Q3 正式结果）

1. **Q2 "多买电如何处理"**：0:00 计划含安全裕度，实际负荷低于计划时多余购电的去向——按计划交付（照常计费、可能进电池）还是其余电出口。候选关系 `grid_unused = grid_contract − grid_delivered` 仅作接口预留。
2. **Q3 多次调整如何累计结算**：D002 的单次替代价式不能直接对多次更新逐项求和；逐次现金流候选 `C = p·q⁰ + Σ_k(−0.5p·(q^{k−1}−q^k)_+ + 1.5p·(q^k−q^{k−1})_+)`（电价 1 时 100→80→100 累计 120）只进单元测试/待裁决说明。
3. **预测首小时映射与冷启动**：附件 3"预报 1 小时"对应发布时刻后第 1 个小时的哪个 10 分钟槽位，Q2 预热窗口与 2 月 1 日起始 SOC 的衔接规则。
4. **映射 A 的墙钟推论（后来已由D003确认）**：官方输入无 `00:00` 列，冻结的"起点对齐"意味着槽 0 = [00:10,00:20)、槽 143 = [0:00+1,0:10+1)（落在次日）；当天 [00:00,00:10) 无输入数据、不参与调度。Q1按"144槽周期首尾相等"（E_144 = E_0）执行；E_143 = E_0读法费用低245.49元，只保留为敏感性对照。
