# Q3 纯合成结算账本测试报告

## 1. 这次验证什么

这次只验证一件事：一个目标槽位的购电计划被多次修改时，费用怎么算。

它不是完整 Q3：

- 没有接附件3；
- 没有使用光伏预测；
- 没有滚动优化；
- 没有跑日窗口或全年。

## 2. 账本口径

按 D007，Q3 的计划费用只能来自版本现金流：

```text
初始费用 = price[target_slot] * q0
上调费用 = 1.5 * price[target_slot] * 增加量
下调冲回 = 0.5 * price[target_slot] * 减少量
```

所以总费用是：

```text
price*q0 + 每次上调费用 - 每次下调冲回 + 紧急购电费用
```

不得再对最终合同量 `q_final` 收一次普通合同费。

## 3. 覆盖的合成反例

| 反例 | 预期 |
|---|---:|
| 不调整 `100` | 100 |
| 单次上调 `100 -> 120` | 130 |
| 单次下调 `100 -> 80` | 90 |
| 来回调整 `100 -> 80 -> 100` | 120 |
| 对 `q_final` 重复收费 | 拒绝 |
| 修改已执行槽位 | 拒绝 |
| Q4 优化价/核算价分离 | 预测价算优化账，真实价算事后账 |
| 紧急购电 | 单独按 5 倍目标槽价计费 |
| 版本跳号 | 拒绝 |

机器结果：`src/q3_ledger_synthetic_tests.py` 9/9 通过，逐项输出见 `experiments/q3_ledger_synthetic_results.json`。

## 4. 结论

Q3 的“结算账本内核”当前可用。

但这只说明“改计划怎么收费”这件事稳了，不代表 Q3 已完成。Q3 仍然不能接入附件3预测，也不能做预测驱动滚动窗口，因为 N3 的点预测到10分钟展开还没有裁决。

当前允许的下一步是：

- 把这个账本接入后续 Q3 纯结算单元测试；
- 或者优先裁决 N3 点预测如何展开到 10 分钟。

仍然禁止：

- Q3 预测驱动滚动窗口；
- Q2-Q4 全年正式运行。
